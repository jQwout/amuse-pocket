## 1. Видение

Одно окно, в котором пользователь:

1. Пишет промпт (или кидает картинку drag&drop'ом),
2. Выбирает модель и модальность (image / video / audio),
3. Жмёт «Сгенерировать» — задание уходит в очередь,
4. Получает результат в галерее с историей, стоимостью и возможностью повторить/доработать.

Ключевой принцип: **ядро генерации не знает про платформу**. Всё, что касается OpenRouter, моделей, очереди заданий и истории — общий Kotlin-код, который потом без изменений подключается к Android.

---

## 2. Почему Compose Multiplatform

Существующая база — Kotlin + Jetpack Compose. Compose Multiplatform (JVM target) даёт:

| Критерий | CMP Desktop | Tauri / Electron |
|----------|-------------|------------------|
| Переиспользование кода из `:app` | Прямое (те же файлы) | Ноль, переписывать на TS |
| Путь в мобилу | Android target бесплатно, iOS возможен | Отдельная разработка |
| Язык/сборка | Kotlin + Gradle (уже есть) | Новый стек в репо |
| Размер дистрибутива | ~60–80 МБ (JVM) | ~10 МБ / ~150 МБ |

Единственный реальный минус — размер дистрибутива, для десктопного pro-инструмента это приемлемо.

**Важно: Compose Desktop в этом репозитории уже доказан.** `tools/lesson-viewer` — работающее JVM-приложение на Compose Desktop 1.7.3 (Kotlin 2.1, Material 3): окно, список, прокрутка, тесты. Фаза 0 перестаёт быть экспериментом — паттерн запуска и сборки уже есть. Отличие: lesson-viewer — самостоятельная Gradle-сборка вне корневого `settings.gradle.kts`, а `:desktop` должен быть модулем корневой сборки, чтобы зависеть от общих модулей `:core:*`.

## 3. Что переиспользуем из `:app`

> Пакеты в актуальной базе — `com.aiopenpocket.*` (миграция с `com.example` уже сделана); пути ниже — относительно `app/src/main/java/com/aiopenpocket/`.

| Компонент | Где лежит | Как переиспользуем |
|-----------|-----------|--------------------|
| `OpenAiCompatClient`, `StreamEvent`, стриминг | `agent/core/llm` | Ядро сетевого слоя: OpenRouter говорит на OpenAI-совместимом API. Выносим в общий модуль |
| `ModelCatalog` | `agent/core/llm` | Расширяем модальностями (image/video/audio модели) |
| `ProviderFallbackChain`, `LlmProvider` | `agent/core/llm` | Абстракция провайдера → база для `GenerationProvider` |
| `ChatMessage`, `FunctionSchema` | `agent/core/llm` | Как есть, для image-gen через chat completions |
| DI (Metro) | `di/` | Metro поддерживает KMP — та же схема в общих модулях |
| Тема / дизайн-система | `ui/theme` | Выносим в `:core:ui`, окно выглядит «родным» к мобиле |
| Библиотека промптов, персоны | `assets/prompts`, `assets/personas` | Формат и загрузчик — общие; на десктопе читаем из ресурсов |
| Хранение ключей | настройки `:app` | Паттерн тот же; на десктопе — файл с правами 600 / keychain ОС |

**Что придётся заменить при выносе в KMP:**

- Retrofit/OkHttp → **Ktor Client** (Retrofit работает на JVM-десктопе, но не в KMP; раз цель — мобила потом, переходим сразу).
- Coil 2 → **Coil 3** (мультиплатформенный, API почти идентичен).
- Room: версия 2.7 уже KMP-совместима — проверяем в фазе 0; запасной вариант **SQLDelight**.

## 4. OpenRouter: покрытие модальностей (проверено 2026-07-29)

Все три модальности покрываются одним провайдером, одним ключом и одним биллингом:

| Модальность | API | Модели (топ) | Особенности |
|-------------|-----|--------------|-------------|
| Картинки | chat completions + `modalities: ["image","text"]` | Gemini image-модели и др. | Синхронный ответ, base64/URL |
| Видео | `POST /api/v1/videos` | Sora 2 Pro, Veo 3.1, Seedance 2.0, Wan 2.7 | **Асинхронный**: job ID → поллинг → скачивание. text-to-video и image-to-video |
| Аудио (TTS) | `POST /api/v1/audio/speech` | GPT-4o Mini TTS, Gemini Flash TTS, Kokoro | Ответ — сырой поток MP3/PCM, пишем сразу в файл |
| Транскрипция | `POST /api/v1/audio/transcriptions` | Voxtral и др. | Бонус: «озвучил идею → получил промпт» |

Абстракцию `GenerationProvider` всё равно закладываем — не как необходимость, а как дешёвую страховку (fal.ai/Replicate подключаемы позже тем же интерфейсом).

## 5. Архитектура модулей

```
ai-open-pocket-2/
├── app/            # существующее Android-приложение — НЕ трогаем до фазы 4
├── core/
│   ├── genai/      # KMP: клиент OpenRouter (chat/images/videos/audio),
│   │               #      GenerationProvider, ModelCatalog, GenerationJob, очередь
│   ├── data/       # KMP: история генераций, настройки (Room KMP или SQLDelight)
│   └── ui/         # KMP: тема, дизайн-система, общие компоненты
└── desktop/        # Compose Desktop: окно, навигация, drag&drop, файловая система
```

Ключевая доменная модель — **`GenerationJob`**: `id`, модальность, промпт, входные файлы, модель, статус (`Queued → Running → Polling → Done/Failed`), результат, стоимость. Очередь заданий — единый механизм для всех модальностей (синхронные картинки — просто job без фазы Polling).

Статусная модель job'а сознательно повторяет подход background-turns из `:app` («ход переживает сворачивание»): статус живёт в БД, а не в памяти, поэтому очередь переживает перезапуск приложения и на десктопе, и потом на мобиле — где это станет тем же foreground-сервисом.

## 7. Бэклог идей (десктоп-специфика, вне фаз)

- **Drag & drop** файлов в окно → image-to-image / image-to-video.
- **Watch-folder**: папка, из которой файлы автоматически уходят в генерацию по шаблону промпта.
- **Сравнение моделей**: один промпт → N моделей рядом (естественное развитие `ProviderFallbackChain`).
- **Агент как промпт-инженер**: чат из `:app` улучшает промпт перед генерацией.
- **Горячие клавиши / keyboard-first UX**, глобальный хоткей «сгенерировать из буфера обмена».
- **Упаковка**: Conveyor или jpackage — установщики Win/mac/Linux из того же Gradle.

## 8. Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Metro DI / Room в KMP ведут себя не как заявлено | Средняя | Проверка в фазе 0; fallback: SQLDelight + ручной DI в общих модулях |
| Вынос кода ломает `:app` | Средняя | В фазах 0–3 `:app` не трогаем вообще (дублирование осознанно), схождение — отдельная фаза 4 |
| Видео-поллинг: длинные задания, обрывы | Средняя | Статусы job в БД → выживает перезапуск приложения, поллинг возобновляется |
| Стоимость видео-генерации при отладке | Высокая | Mock-провайдер за `GenerationProvider` для разработки; дешёвые модели (Veo Lite) по умолчанию |
| Размер JVM-дистрибутива | Низкая | Принимаем как данность для pro-инструмента |
