## 1. Что реально даёт Meta Model API

Базовый URL `https://api.meta.ai/v1`, авторизация `Authorization: Bearer $MODEL_API_KEY`. Три протокола: Responses, **Chat Completions** (`POST /v1/chat/completions`, OpenAI-совместимый), Messages (Anthropic-совместимый).

| Модель | id | Вход → выход | Цена (за 1M токенов) | Лимиты |
| --- | --- | --- | --- | --- |
| Muse Spark 1.3 / 1.2 / 1.1 | `muse-spark-1.3` … | текст, картинка, **видео**, аудио, PDF → текст | $1.25 вход / $4.25 выход / $0.15 кеш | 3000 RPM, 4M TPM |
| Muse Wonder (preview) | `muse-wonder-1.0` | то же | $4.00 / $20.00 / $0.20 | 3000 RPM |
| Muse Image | `muse-image-1.0` | текст + картинка → **картинка** | **$0.01 за картинку** | 150 RPM |
| Muse Voice Transcribe | `muse-voice-transcribe-1.0` | аудио → текст | $0.18 за час аудио | 256 стримов |
| SAM 3.1 | `sam-3.1` | промпт + картинка/видео → боксы и маски | $0.20 за 1000 кадров видео, $2.50 за 1000 картинок | 3000 RPM |

Контекст у Spark/Wonder — 1 048 576 токенов.

**То же через OpenRouter** (проверено по `/api/v1/models` 2026-10-23, цены те же, что у Meta напрямую):

| Модель | id на OpenRouter | Заметка |
| --- | --- | --- |
| Muse Spark 1.3 / 1.2 / 1.1 | `meta/muse-spark-1.3` … | тулы, видео на вход; проходит фильтр нашего живого каталога (tools + text) |
| Muse Wonder | `meta/muse-wonder` | тулы |
| Muse Image | `meta/muse-image` | `POST /api/v1/images`, ответ `data[].b64_json` + `media_type`; цена в токенах вывода, ≈ $0.01 за картинку |
| Contributor-версии | `meta/muse-spark-1.3-contributor`, `…-1.2-contributor` | **уже видны в нашем выборе модели** — отфильтровать |
| SAM 3.1, Voice Transcribe | — | только прямой Model API |

**Чего НЕТ (важно не обещать в заявке):**
- **видеогенерации** — ни одной модели с видео на выходе; видео только на вход;
- **TTS** — Voice Transcribe только распознаёт речь, синтеза нет;
- бесплатных кредитов в документации не обещано (сторонние обзоры пишут про $150 кредитов участникам — проверить в письме о допуске, не планировать на это).

**Подводные камни совместимости** (наш `OpenAiCompatClient` шлёт `model`, `messages`, `max_tokens`, `stream`, `stream_options`, иногда `temperature` и `top_p`, плюс `tools`):
- `temperature` **и** `top_p` одновременно → HTTP 400. В нашем NIM-каталоге два энтри задают оба (`inkling`, `minimax-m3`) — в мета-каталоге так делать нельзя;
- `n > 1`, `logprobs: true`, `stop`, `logit_bias`, `modalities`, `audio`, `text.format` → 400;
- `reasoning_effort: "none"` → 400, «Muse Spark always reasons» (латентность первого токена выше, чем у flash-моделей NIM);
- `max_output_tokens` отвергается, `max_tokens` принимается как deprecated (наш путь работает), канонично — `max_completion_tokens`;
- **строгий реплей тул-вызовов**: каждое assistant-сообщение с `tool_calls` должно прийти с парными `role:"tool"` + `tool_call_id`, иначе 400. Это главный риск для нашего агентского лупа;
- нестриминговые долгие запросы могут отдать 504; стрим от этого избавлен — у нас везде стрим;
- `stream_options.include_usage` в документации протокола не упомянут — проверить первым же запросом, иначе учёт расхода отвалится на 400.

## 4. Фаза B — картиночные уроки на Muse Image (1–1.5 дня)

Сейчас шаг урока `{"type":"image"}` умеет: `asset` (бандл, первым — чтобы урок работал оффлайн), `url` (сетевой фолбэк), `caption`, `imageKey`, `alt`; рендерит `ImageCardView` через Coil с фиксированным 16:9 и светлой подложкой. В `assets/lessons/images` лежат 13 рукописных SVG. Менять рендер не нужно — он уже берёт `url`, а Coil принимает `file://`.

- `ImageGenClient` (новый, рядом с `OpenAiCompatClient`), один на оба маршрута — формы запроса и ответа совпадают. OpenRouter: `POST /api/v1/images`, `model: "meta/muse-image"`, поля `aspect_ratio`, `size`, `output_format`, `n`, ответ `data[].b64_json` + `media_type`. Meta напрямую: `POST /v1/images/generations`, тело `{"model":"muse-image-1.0","prompt":…,"n":1,"size":"1536x1024"}`, ответ — `data[0].b64_json` (по умолчанию) либо `url`. Параметры `size`/`output_format` по сторонним обзорам (webp по умолчанию, есть png/jpeg) — **сверить с `/docs/api-reference/images/create-image` перед кодом**. Правка картинки — `POST /v1/images/edits`.
- `LessonImageGenerator`: промпт → хеш → кеш `filesDir/lesson_images/<hash>.webp` → `file://` URI. Повторный проход урока картинку не перегенерирует.
- `LessonStep` + поле `imagePrompt`; `LessonChatController.buildImageCardSpec` подставляет готовый файл в `url`. Порядок источников: `asset` (бандл) → сгенерированный файл → сеть → «Нет изображения». Оффлайн-урок не ломается никогда.
- Два режима, и нужны оба:
  1. **Предгенерация** — скрипт гоняет промпты из уроков и кладёт результат в `assets/lessons/images` (26 уроков × ~3 картинки ≈ **$0.8** разово). Это новая база вместо/рядом с рукописными SVG: уроки становятся картиночными для всех, включая оффлайн.
  2. **«Нарисуй под меня» на ходу** — кнопка на шаге урока: картинка генерируется под профиль и язык пользователя (его домен, его пример). Это то, что на демо выглядит как магия, и ровно то, чего не даёт статичный курс.
- Учёт расхода: $0.01 за картинку в ту же карточку расхода — у нас уже есть честный счётчик, и он играет на номинацию по UX/доверию.
- traxer: фича `lesson-generated-images` (rationale: почему картинки генерируются, а не рисуются руками, и почему бандл остаётся первым источником).

## 5. Фаза C — «видео» в уроках (1–1.5 дня)

Прямой видеогенерации у Meta в API нет — значит «видео-урок» делаем двумя честными путями.

**C1. Сториборд-видео (упаковка).** 4–6 кадров Muse Image на один урок + анимация в Compose (crossfade + медленный Ken Burns) + озвучка системным Android TTS (оффлайн, бесплатно). Ощущается как видео, целиком наш код, ничего не рендерим и не выгружаем. Применить к 1–2 ключевым урокам (`how_llm_reads`, `react_loop`), а не ко всем.

**C2. Видео на ВХОД (главное демо).** Muse Spark принимает видео, SAM 3.1 сегментирует видео ($0.0002 за кадр). Урок: человек снимает 5–10 секунд своей комнаты / полки / этикетки — модель объясняет, что видит, и дальше урок говорит с ним на его материале; мини-агент «питание» уже устроен вокруг фото продукта, видео — следующий шаг. Это попадание в *Build for Your World* и то, чего веб-участник на ноутбуке не покажет: камера, оффлайн-фолбэк, личные данные не уходят дальше выбранного вендора. Работы больше, чем кажется: `ChatMessage.content` сейчас строка, для видео/фото на вход нужны части контента (multimodal content parts) в `ChatMessage` и `OpenAiCompatClient`. Spark принимает видео и через OpenRouter; SAM 3.1 — только с A2.

Рекомендация: C2 — ядро демо, C1 — обёртка для одного-двух уроков. Если время кончается, C1 режем первым.

- Демо-видео на 3 минуты *(старый набросок; актуальный сценарий — в сабмишн-доке)*: мини-агент решает задачу → урок с картинкой, сгенерированной под тебя → видео-вход («модель смотрит на твою полку») → карточка расхода за неделю (показываем, что считаем чужие деньги честно).
- Описание проекта: один абзац «зачем» (AI-грамотность внутри живого агента), один «как» (Muse Spark в тул-лупе, Muse Image в уроках, видео-вход, всё на телефоне), один «что дальше».
- Запас: сабмишн за сутки до дедлайна (4 ноя 21:00 ET — это ночь по московскому времени).

## 7. Риски

| Риск | Что делаем |
| --- | --- |
| **Вклад «сделано на хакатоне» не читается** | Подтверждено 26 окт: за это обещана немедленная дисквалификация, а окно — 27 окт — 4 ноя, то есть вся Muse-часть 23–25 окт в него не попадает. Решение: заметную часть делать в окне, в сабмишне отдельный раздел «before / during» с диапазоном коммитов, в ролике показывать сделанное в окне |
| **Маршрут через OpenRouter не засчитают на Stage 1** | Stage 1 требует «Meta Model API и/или открытые веса Meta»; Muse Spark закрытая, OpenRouter — не Meta API. Серая зона на отсеве без баллов → A2 обязательна: основной маршрут в демо-сборке — прямой Meta Model API, OpenRouter запасной |
| **Репозиторий закрыт, в истории ключ** | Открыть обязаны; в истории APK с ключом `AIzaSyDSmlm5Mc1g…`. Порядок — раздел 4 сабмишн-дока: отозвать ключ, вычистить `.build-outputs/` из истории, пересканировать, force-push, открыть |
| **Проект похож на anti-project** | В списке запрещённых — простые «AI for Education» чат-боты и AI Nutrition Coach. Подача: платформа сборки агентов в заголовке, обучение как её часть; агента про питание в демо не показывать |

## 8. Что НЕ делаем

- Не выпиливаем NIM. Muse идёт через OpenRouter (A1), прямой META при необходимости встаёт третьим равноправным вендором (A2); BYOK остаётся (это и есть наша тема доверия).
- Не трогаем план-движок и не меняем фреймворк (см. решение «freeze rails»).
- Не тащим сюда RevenueCat, подписки и рекламу из плана Shipaton — другой хакатон, другие критерии.
- Не переписываем 26 уроков: картинки добавляются поверх существующего JSON-контракта.
