# План: «Traceability Cloud» — карта фича↔код↔причина для AI-агентов

> Цель проекта: связать **требования/фичи ↔ код ↔ причину изменения** (git) через
> облако тегов и флаги в коде, чтобы AI-агент (и человек) не терял контекст между
> сессиями. Реализуется как **отдельный standalone-инструмент**, а не правки в этом репо.

## Ключевые решения (зафиксировано)

1. **Отдельный проект**, не правки в текущем приложении.
2. Реализация через **хуки + скиллы** для Claude Code и портируемо на другие
   агенты (Codex, Cursor и т.д.).
3. **Языко-независимо** — работает для любого ЯП, не только JVM.
4. Реестр = **YAML/JSON** + универсальный тег-маркер в комментариях.

Следствие из (3): теги НЕ привязываются к KDoc (это только Kotlin/Java). Нужен
универсальный маркер в комментарии, одинаково парсящийся в `//`, `#`, `--`,
`/* */`, `<!-- -->`. Сканер не парсит язык, а ищет текстовый маркер — поэтому
работает везде из коробки.

## Принцип архитектуры

Одно **языко-независимое CLI-ядро** + тонкие адаптеры под каждого агента.
Агент-специфика (хуки Claude, rules Cursor, AGENTS.md Codex) — обёртки, которые
вызывают ядро. Вся логика — в ядре.

```
┌─────────────────────────────────────────────┐
│  Адаптеры (тонкие):                          │
│  Claude hooks+skills · Cursor rules · Codex  │
└───────────────────┬─────────────────────────┘
                    │ вызывает
┌───────────────────▼─────────────────────────┐
│  CORE CLI (ядро, языко-независимое)          │
│  scan · build · check · link · cloud         │
└──────┬──────────────┬──────────────┬─────────┘
       │              │              │
   код (regex)   реестр.yaml      git (trailers)
```

## Фаза 0 — Спецификация (фундамент, без кода)

Зафиксировать два формата — это контракт всего проекта.

### Универсальный тег-маркер (в комментарии любого языка)

```
@trace feature:search flow:find-anime
```

```python
# @trace feature:search flow:find-anime
def search_anime(q): ...
```

```rust
// @trace feature:search
fn search_anime(q: &str) {}
```

```html
<!-- @trace feature:search -->
```

Сканер ищет регуляркой `@trace\s+(.+)` — язык не парсится, поэтому поддерживается
любой ЯП сразу. Привязка к символу (имя функции) — опциональный слой через
tree-sitter в поздней фазе; в v1 достаточно `файл:строка`.

### Схема реестра (`traceability.yaml` — источник правды)

```yaml
features:
  search:
    title: "Поиск аниме"
    flows: [find-anime]
    spec: "TZ.md#5"                 # ссылка на ТЗ
    rationale: "Найти тайтл за <3с" # ← ПОЧЕМУ (ключ против потери контекста)
    code: []                        # ← автозаполняется сканером, руками не трогать
```

## Фаза 1 — Core CLI (MVP-ядро)

Команды (имена — ориентир):

- `trace scan` — обходит репозиторий (`git ls-files` / ripgrep), собирает все
  `@trace`-маркеры → строит карту `фича → [файл:строка]`.
- `trace build` — мёржит сканированное в `code:` реестра.
- `trace map` — печатает карту (для человека и для контекста агента).

**Язык реализации ядра:** рекомендую **TypeScript (Node)** или **Python** — обе
родные для экосистемы AI-агентов (хуки/скиллы), легко ставятся (`npx`/`pipx`),
кроссплатформенны. Для single-binary-дистрибуции — Go/Rust, но это усложнит старт.

---

## Фаза 2 — Drift-детектор (главная ценность)

`trace check` сверяет три источника и печатает расхождения:

- тег в коде → нет в реестре;
- фича в реестре/ТЗ → нет кода;
- символ/файл меняется в git, но не несёт тега («код без объяснения»).

Exit-code ≠ 0 → можно вешать на CI и pre-commit.

---

## Фаза 3 — Git как «причина и следствие»

- Соглашение о commit-trailer: `Trace: feature/search` (языко-независимо).
- `trace why <feature>` → `git log --grep` по тегу = вся история «почему менялось».
- `trace cloud` → облако тегов: размер = объём кода/частота изменений (churn) по
  фиче. Вывод в Markdown/HTML — это и есть «облако тегов» как карта горячих точек.

---

## Фаза 4 — Интеграция с Claude Code (хуки + скиллы)

- **SessionStart hook** → запускает `trace map` + `trace check` и вставляет
  результат в контекст. Это и есть решение исходной проблемы: каждая новая сессия
  стартует с актуальной картой фича↔код↔почему и списком расхождений.
- **Skills (слэш-команды):** `/trace-check`, `/trace-link <feature>` (привязать
  текущие правки к фиче), `/trace-why <feature>`.
- **PostToolUse hook** (опц.) → после Edit/Write напоминает проставить `@trace`,
  если новый код без тега.

---

## Фаза 5 — Портирование на другие агенты

Ядро одно, адаптеры тонкие:

- **Cursor** → правило в `.cursor/rules` + вызов CLI.
- **Codex / прочие** → запись в `AGENTS.md` + git-хук
  (`pre-commit`/`prepare-commit-msg`), не зависящий от агента.
- Универсальный фолбэк — git-хуки: работают с любым инструментом, даже без AI.

---

## Фаза 6 — Синхронизация (только ручная, через ревью)

Решение: **никакой автоматики**. Синк всегда инициирует человек, изменения
проходят через ревью (PR), а не применяются молча.

- `trace check` лишь **сообщает** о расхождениях ТЗ↔код (read-only, в отчёт/CI).
- `trace plan <feature>` — вспомогательный: печатает чеклист/заглушки как
  предложение, человек сам решает, что брать.
- Применение правок (обновление `traceability.yaml`, ТЗ или кода) выполняет
  человек/агент осознанно и оформляет **через pull request** — diff виден,
  есть ревью, есть откат.
- ❌ Авто-генерация кода из ТЗ и авто-правка ТЗ из кода — НЕ делаем. Инструмент
  только обнаруживает дрейф и предлагает; решение и коммит — за человеком.

## Рекомендуемый MVP (первый чат реализации)

Минимальный срез, который уже полезен:

1. Спека тег-маркера + схема `traceability.yaml` (Фаза 0).
2. `trace scan` + `trace check` на Python/TS (Фазы 1–2).
3. SessionStart-хук для Claude Code (Фаза 4).

Этого достаточно, чтобы инструмент начал реально держать контекст между сессиями.
Git-трейлеры, облако тегов и портирование — итерации поверх.

---

## Риски / на что смотреть

- **Привязка тега к символу** в языко-независимом режиме неточна → в v1 живём с
  `файл:строка`, символьную точность добавляем через tree-sitter позже.
- **Дисциплина тегирования** — главный риск любой traceability. Закрывается
  PostToolUse-хуком и `check` в CI.
- **Дубли/переименования фич** — нужен `trace rename` и валидация ID по реестру.

## Контекст происхождения

Документ возник из обсуждения проблемы «Claude теряет контекст между сессиями».
Сам факт, что этот план хранится в репозитории (а не в чате), — иллюстрация
решения: контекст живёт в git, а не в памяти агента.
