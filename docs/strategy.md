# Стратегия: visibility → exit

> **Дата:** 2026-06-24 · **Статус:** активный план, придерживаемся
> **Связано:** [business-eval.md](./business-eval.md) — полная аналитика; этот файл — короткий «север», к которому возвращаемся при каждом решении.

---

## 0. Стратегическая цель (north star)

**Стать заметными в глобальном AI-dev сообществе за 9–12 месяцев и продаться стратегу.**

Не ARR. Не unit-economics. Не enterprise.
Это меняет почти всё: что мы строим, что меряем, что **не** делаем.

**Целевой диапазон сделки: $1–10M на команду (acqui-hire).** Это **достаточно**, не «компромисс». Из этого следуют ключевые тактические выводы, которые задают всё дальнейшее:

- **Time-to-exit > size-of-exit.** Шесть месяцев до сделки на $2M лучше, чем восемнадцать до сделки на $8M.
- **Не растим команду** ради «видимости масштаба». Acqui-hire на 2–3 человек — нормальный исход.
- **VC-раунд не нужен.** Любое внешнее финансирование размывает долю и удлиняет сроки до сделки (инвесторы хотят больший exit). Bootstrap или микро-grant (Y Combinator? AI-grant-программа Anthropic/OpenAI?) — потолок.
- **Терпим худшую unit-economics** в продукте ради скорости — оптимизируем сигнал, не себестоимость.
- **Не ждём «правильной цены».** Первый разумный оффер от стратега — берём, если он в диапазоне.

## 1. Что это означает в практических решениях

| Решение | Acquisition-стратегия | Что **не** делаем |
|---|---|---|
| Цена | **Free навсегда + опц. Pro $9.99 как сигнал ARR**, не воронка | Не строим B2B sales, не гоняемся за корпоративными контрактами |
| Метрика недели | DAU, GitHub stars, X-импрешны, demo-видео-views | НЕ MRR, НЕ retention day-30, НЕ CAC/LTV |
| Канал | Контент (X, HN, PH, YouTube), open source | НЕ performance-маркетинг, НЕ SEO long tail |
| Roadmap | Демо-достойные фичи (агент трогает реальный телефон → видео виральное) | НЕ внутренние tooling-фичи, которых не видно снаружи |
| Open source | **Открыть скилл-архитектуру + уроки**, лицензия Apache-2.0 | Не открывать всё ядро (нужна узнаваемая «компания», а не просто либа) |
| Платформы | iOS как можно раньше — половина AI-X-audience на iPhone | НЕ Windows / Web-десктоп до экзита |

**Эвристика принятия решений:** *«Если бы Anthropic/Cursor/Duolingo увидели это завтра — это сделало бы их хотеть купить нас сильнее или слабее?»* Если ответ «слабее» или «нейтрально» — не делаем.

## 3. Сигналы, которые покупают

Что **на самом деле** смотрят M&A-команды в AI-secone 2026 (по публичным сделкам Adept→Amazon, Inflection→Microsoft, Multi→OpenAI, Character→Google):

1. **DAU и кривая роста** — линейные продукты не покупают, exponential покупают.
2. **Brand awareness** в нише — упоминания на X / в подкастах / в блогах.
3. **GitHub stars и community** — proxy для культурного влияния.
4. **Distinctive IP** — что-то, что нельзя сделать «у себя за квартал». Наша скилл-архитектура (`docs/lessons/01-sozdanie-navykov.md` §§ 2, 5) — именно это.
5. **Team caliber** — кого фактически покупают.
6. **Strategic adjacency** — закрываем дыру в их roadmap.

Что **не** покупают (или покупают с дисконтом):
- ARR $50–500K — слишком мало для revenue-multiple, слишком много для acqui-hire (мешает «купить только команду»).
- Enterprise pipelines без deals — pipe гадается, deals — нет.
- Большая команда — дороже acqui-hire.

**Sweet spot:** маленькая команда (2–5 чел.) + сильный продукт + видимая аудитория + чистая IP + zero-to-low revenue.

## 4. Перепрошитый 90-дневный план (под visibility, не ARR)

### Альфа: 0–6 недель — заложить вирусную механику и закрыть pre-launch
Цель: **выйти на запуск с готовым «гнездом» внимания, а не с холодного старта.**

1. **100 RU/Android альфа-тестеров** — как раньше, источник продуктовых инсайтов. Без выручки.
2. **Чистка артефактов** для возможности красивого open-source-старта:
   - `com.example` → реальный package
   - `debug.keystore.base64` из git вычистить, history переписать (`git filter-repo`)
   - Минимальный CI с unit-тестами
3. **«Сезон 2» уроков 8–10:** function calling, MCP, мульти-агент. Это контент для viral-demo-роликов.
4. **Demo-видео #1:** «Я научил телефон ставить мне встречи через AI-агента за 60 секунд» — 60-90 сек., iOS Reminders / Google Calendar tools в действии. Эта запись поедет на X, HN, PH.
5. **Twitter/X-аккаунт в режиме build-in-public:** 3–5 постов в неделю про разработку, видео тулов, скриншоты уроков. Накопить 500–1000 подписчиков **до** запуска. На запуск это превращается в первичный bump.
6. **Lurk targets:** подписаться, читать, комментировать у swyx, simonw, alexalbert__, deepseek_ai, anthropicai, cursor_ai, dr_cintas. Стать узнаваемой репликой в треды.

### Pre-beta: 6–12 недель — снять платформенные ограничения
7. **EN-локализация.** Без неё HN/PH не работают.
8. **iOS-релиз через Compose Multiplatform.** Хотя бы read-only beta. Без iOS — половина X-аудитории нас не увидит.
9. **Открыть исходник скилл-архитектуры** (`DrivenUiEngine` + промпт-формат + примеры) отдельным репо `agent-skills`, Apache-2.0. Это магнит для GitHub stars и обсуждения.
10. **Paid tier $9.99/мес. с trial 14 дней** — не как воронка, как **сигнал, что есть платящие** (важно для M&A-pitch). Конверсия 2–5% — норм, не оптимизируем.
11. **Лендинг в качестве «product company»**, а не «pet project»: команда, манифест, blog с инженерными постами.

### Beta launch: 12–16 недель — главный шум
12. **Скоординированный launch-week:**
    - Понедельник: Show HN с постом «I built a pocket AI agent trainer — every lesson is a prompt, every tool is real»
    - Вторник: Product Hunt
    - Среда: thread на X с demo-роликом
    - Четверг: пост в r/LocalLLaMA + r/ClaudeAI + r/Replit
    - Пятница: ретроспектива «what we learned, here's the data» — это превращает launch в постоянный контент.
13. **Outreach по подкастам:** Latent Space (swyx), Lex (длинный шот), MLST, How I Built This (длинный), Practical AI. Pitch: «we built the Duolingo for AI agents — here's why it matters».
14. **Demo-видео #2 и #3** — приурочить к launch.
15. **Цель к концу 16-й недели:** 5K GitHub stars, 50K+ X-импрешн на главные посты, 10K+ install, 1 публикация в TechCrunch / The Verge / Engadget (тёплый pitch через сеть).

### После launch: 4–9 месяцев — войти в радар покупателей
16. **Ежемесячный demo-day** — публичный stream / X Space «what's new this month». Это форсирует ритм публичной видимости.
17. **Партнёрство с одним из MCP-серверов** (Postgres, Brave Search, Slack) — co-marketing.
18. **Серия инженерных постов:** «как мы рисуем UI через LLM», «как мы делаем скиллы переносимыми», «почему мы выбрали Compose Multiplatform». Это контент, который приводит acquirer-инженеров.
19. **Появиться на конференции:** AI Engineer Summit, droidcon, GDG-events. Презентация = ещё одна точка узнаваемости.
20. **Тёплые контакты с DevRel / corp-dev** Anthropic, Duolingo, Replit, Cursor через X. Не pitch — но «look at what we built» периодически.

### Месяцы 9–12 — момент истины
21. **Если виральность пошла:** проактивный pitch corp-dev top-3. Подготовить deck «strategic fit slide» для каждого из них отдельно.
22. **Если виральность не пошла:** пивот — либо в B2B-corp-обучение (плановый план Б), либо честный сан-сет.

## 5. Что мы НЕ делаем (явно)

- Не строим enterprise-sales-команду
- Не гонимся за SOC 2 / EU AI Act до сделки (это покрывает покупатель)
- Не делаем мультиплатформенный десктоп до экзита
- Не пилим много локалей (EN + RU достаточно для виральности)
- Не оптимизируем retention day-30 (ROI ниже, чем у поступающего внимания)
- Не пилим конструкторы скиллов в UI пользователя (open source даёт это «бесплатно»)
- Не интегрируемся с CRM / Slack / Outlook (это для B2B, не для виральности)

## 6.5 Защита от «скопируют, не купят»

Главный риск всей стратегии. Полная защита невозможна — большой игрок с deep pockets копирует продукт за 3–12 мес. Реалистичная цель: **сделать копирование дороже и медленнее, чем покупку**, и сделать так, чтобы решение «build vs buy» в их совете вообще обсуждалось.

### Что **не** защищает (хотя соблазн использовать велик)
- Патенты в этой области — прайор-арт везде, бесполезно.
- «Мы сделали первыми» — fast followers в AI выигрывают чаще, чем first movers.
- Trade secrets / закрытый код — реверс-инжиниринг работающего приложения занимает недели.
- «У нас лучше UX» — копируется за месяц.
- Open source кода — могут просто форкнуть.

### Что реально защищает (по приоритету)

**1. Скорость к exit.** Главная защита. Чем быстрее мы достигаем «купить дешевле, чем построить», тем меньше у них времени принять решение «build». Сравнительная стоимость:
- 6 месяцев работы 4–6 senior-инженеров в Anthropic ≈ $1.5–3M в полностью загруженных costs.
- Acqui-hire нас на тех же $1.5–3M = они получают готовый продукт + команду + community, экономят 6 месяцев календарного времени.
- **Чем дольше мы существуем — тем больше у них стимула строить самим.** На 3-м месяце build-vs-buy 50/50, на 18-м месяце они уже строят (потому что их собственный launch уже близко).

**2. Community + brand как стандарт, не продукт.** Открываем **скилл-формат** как «AI Open Pocket Skill Schema» / `agent-skills` repo с явным брендом. Anthropic копирует приложение — ОК, но если они хотят совместимость со 100+ community-skills, им придётся либо адоптировать наш schema (валидация бренда), либо фрагментировать сообщество (медленно). В обоих случаях они теряют темп. Прецеденты: LangChain доминирует не лучшей либой, а тем, что **стал стандартом**.

**3. Multi-provider, не Claude-only.** Если мы 100%-Claude-приложение, Anthropic не нужно нас покупать — они владеют моделью. Текущая архитектура NIM → Groq → GitHub Models уже правильная: мы — **стратегический ассет**, а не captive user. То же про Duolingo: если их интересует «not married to one LLM», multi-provider — плюс.

**4. Прямые отношения до оффера.** M&A почти всегда начинается со «знакомый знакомому». Тактически:
   - Tom Brown / Mike Krieger / Daniela Amodei (Anthropic) — добиться, чтобы один из них хотя бы лайкал наши X-посты.
   - Amjad Masad (Replit), Michael Truell (Cursor), Luis von Ahn (Duolingo) — аналогично.
   - Это не «pitch» — это «look at what we built» периодически, через X, через интервью на их подкастах (Latent Space часто гостит таких).
   - Хорошие лиды появляются у людей, кого M&A-команды покупателя видят в Twitter feed своего CEO.

**5. Distribution > technology.** На момент оффера у нас должно быть **то, что они не могут быстро купить иначе**: 10K+ активных пользователей именно в AI-dev сегменте. Anthropic может построить технологию за квартал, но «10K AI-engineers, обученных на нашей платформе» — нельзя. Прецеденты:
   - WhatsApp: 50 сотрудников, 450M пользователей → Facebook купил за $19B
   - Instagram: 13 сотрудников, 30M пользователей → Facebook купил за $1B
   - В обоих случаях дистрибуция была moat, не технология.

**6. Конкурирующие интересы покупателей.** Один интересант → они либо демпингуют, либо строят сами. Три интересанта → они конкурируют, и решение «build» проигрывает по срокам. Тактика — параллельно держать тёплый контакт с Anthropic + Duolingo + Cursor/Replit + Yandex/Sber. Не блефовать — реально культивировать все четыре линии.

**7. Defensive M&A leverage.** Если Anthropic не уверены, нужен ли им продукт, но **точно не хотят, чтобы нас купил Duolingo или Replit** — они купят защитно. Прецедент: Instagram → Facebook в 2012 (Facebook боялись Twitter / Google). Это работает, только если другие интересанты видимы.

**8. Acquireability hygiene с первого дня.** Чистый код, чистая IP, чистый cap table, чистые лицензии, без долгов перед сотрудниками. Любая friction в due diligence удлиняет сделку на месяцы — а время работает против нас (см. п. 1). Конкретно сейчас:
   - `com.example` → реальный namespace **до** первой публичной видимости.
   - `debug.keystore.base64` из git вычистить с переписыванием history.
   - Контракты с любыми контрибьюторами (если будут) — CLA или MIT-license с самого начала.
   - Никаких GPL-зависимостей (заразны для проприетарного продукта покупателя).

**9. Optionality narrative.** В разговоре с покупателем всегда должна быть **видимая опция Б**: «если не вы — мы возьмём $2M seed от a16z и продолжим расти». Не блеф — это должно быть реалистично. Опция-Б создаёт **срочность** у покупателя.

**10. Не быть слишком привязанными к одному vertical.** Если мы строго «учим Claude-разработчиков» — Anthropic смотрит на нас как на «свой сегмент, построим». Если мы «учим работать с агентами вообще» (включая MCP, LangChain, function-calling у любого провайдера) — мы инфраструктура, и каждый игрок боится, что нас купит конкурент.

### Эвристика на каждое решение
*«Делает ли это нас более защищаемой целью M&A — увеличивает ли community, скорость, многосторонний интерес, чистоту IP?»* Если нет — не делаем.

### Тактический минимум первых 90 дней
- Открыть `agent-skills` репо как **стандарт скилл-формата**, не как «наш код».
- Multi-provider в коде явно показывать как фичу, не как имплементационную деталь.
- Параллельно поддерживать минимум **2 направления M&A-разговоров** до конца beta launch.
- Чистка артефактов (`com.example`, keystore, лицензии) — до первого публичного видео.

## 7. Риски этой стратегии (честно)

1. **Viral attempt не выстрелит.** Большинство launch-week не выстреливают. Митигация: подготовленная аудитория до запуска (X в build-in-public + альфа-тестеры).
2. **Acquirer waits too long.** Большие игроки могут долго смотреть → деньги кончатся. Митигация: paid tier даёт минимальный runway-сигнал; план Б — B2B-corp-обучение.
3. **Acquirers скопируют, не купят.** Anthropic может просто построить такое же. Митигация: distinctive IP (скилл-архитектура + педагогика) + скорость + community.
4. **EU AI Act compliance может всплыть у покупателя** на due-diligence. Митигация: держать архитектурную чистоту (local-first, no PII в облако без согласия) изначально.
5. **Соблазн «дождаться оффера получше».** Когда первый оффер $1–3M прилетает, легко начать тянуть в надежде на $10M+ через полгода. Митигация: записать «первый разумный оффер в диапазоне — берём» в §0 и держаться, потому что через полгода продукт может выдохнуться или большой игрок построит сам.

## 8. Один абзац, к которому возвращаемся при каждом решении

> Мы строим **самый узнаваемый «карманный учитель по AI-агентам»** на глобальном рынке за 9–12 месяцев. Каждая фича, каждый пост, каждое видео — это либо узнаваемость, либо отличающая IP, либо ничто. Если решение не помогает первым двум — его нет в roadmap. Покупатель смотрит на: график роста DAU, distinctive tech, узнаваемое имя в нише, маленькую команду. Мы оптимизируем эти четыре переменные, всё остальное — подчинено им.
