# Доработка промпта нейросетью и теги файлов в тексте промпта

Дата: 2026-08-05
Модуль: `desktop/` (`:core-genai`, `:app-desktop`)
Фича traxer: `desktop-genai-client-4c63b6`

## Задача

Две вещи, которых на экране генерации не хватает:

1. **Доработка промпта нейросетью.** Жмёшь кнопку — открывается модальное окно, выбираешь готовое
   действие («детальнее свет», «на английский») или пишешь свою команду, снизу переключаешь модель.
   Нейросеть переписывает промпт целиком, результат встаёт прямо в поле формы: изменённые куски
   подчёркнуты, рядом кнопка «Вернуть оригинал».

2. **Теги файлов внутри промпта.** У вложений уже есть теги. Нужно уметь сослаться на файл прямо в
   тексте: пишешь `@туман`, всплывает автодополнение со списком тегов (миниатюра, имя файла, роль),
   выбираешь — и при отправке `@туман` разворачивается в ссылку на конкретную картинку.

## Что уже есть в коде

- `InputAttachment(path, role, tags)` — теги у файлов уже собираются в UI (`AttachmentsField`).
- `describeAttachments(prompt, images)` (`OpenRouterProvider.kt`) — дописывает в конец промпта строку
  «Исходники — фон: trassa_fog_11.jpg (ночь, туман); …». То есть теги уже доезжают до модели, но
  хвостом, а не там, где о них написано.
- `POST /chat/completions` уже используется для картинок — транспорт для текстового вызова есть.
- `GenaiCatalogService.modalityOf` качает весь каталог OpenRouter и **выбрасывает текстовые модели**:
  распознаются только `image`/`video`/`audio` в `architecture.output_modalities`.
- Модальный диалог с поиском и список моделей — `ModelPickerPanel` / `ModelPickerList`.

## Принятые решения

### Р1. Вызов текстовой модели идёт мимо очереди

Отдельный `PromptRefiner` в `:core-genai`. Не задание, не артефакт, не история.

**Почему не `GenerationModality.TEXT`:** enum означает «какой артефакт получится на выходе».
Доработка промпта файла не производит. Добавить TEXT — значит завести ветку в каждом `when(modality)`
провайдера, разрешить очереди принять задание, которое ничего не создаёт, и притащить в списки моделей
всё текстовое, что есть у OpenRouter.

### Р2. `@тег` разворачивается в момент отправки

В поле лежит обычный текст с `@туман`. Чистая функция подменяет его при submit.

**Почему не при вставке:** текст сказал бы «изображение 2», а после удаления первого файла ссылка
молча указывает не туда. **Почему не структурные спаны:** обычное текстовое поле не протащит
идентичность спанов через произвольное редактирование, машинерия несоразмерна задаче.

**Висячая ссылка не замалчивается.** `@туман` без файла подсвечивается в поле цветом ошибки, запуск
заблокирован — как при пустой модели. Отправлять модели слово «@туман», которое ей ничего не говорит,
нельзя.

### Р3. Список текстовых моделей — живой, а не выдуманный

`GenaiCatalogService` при разборе ответа попутно собирает модели, у которых в `output_modalities`
есть `text` и нет `image`/`video`/`audio`, в отдельное поле снапшота. `GenerationModality` не
меняется. В `models.json` лежит короткий сид на случай, когда живого списка ещё нет (первый запуск,
нет сети) — он помечен как страховка, слаг всегда можно ввести руками.

### Р4. Пресеты доработки — встроенная константа

Четыре штуки: «Доработать», «Детальнее свет», «На английский», «Короче». Пользовательский файл
пресетов не заводим: escape hatch — поле своей команды. (YAGNI; при надобности повторим схему
`PromptLibrary`: встроенные + файл пользователя.)

## Архитектура

### `:core-genai` — новое

**`PromptRefiner.kt`**

```kotlin
class PromptRefiner(httpClient: HttpClient, apiKey: () -> String, baseUrl: String) {
  suspend fun refine(prompt: String, instruction: String, model: String): RefineResult
}

sealed interface RefineResult {
  data class Ok(val text: String, val costUsd: Double?) : RefineResult
  data class Failed(val message: String) : RefineResult
}
```

`POST $baseUrl/chat/completions` без поля `modalities` — тот же ключ, тот же движок. Системное
сообщение объясняет модели, что она переписывает промпт для генератора картинок и обязана вернуть
ТОЛЬКО текст промпта, без пояснений. Пустой ответ или ответ без текстовой части — это `Failed`,
а не пустая строка в поле пользователя.

`costUsd` берётся из `usage.cost`, как в генерации. Может быть `null` — тогда UI про деньги молчит.

**`PromptTags.kt`** — чистые функции, без сети и без Compose:

```kotlin
/** Уникальная метка тега → индекс файла. «туман», «туман-2» при совпадении у разных файлов. */
data class TagRef(val label: String, val attachmentIndex: Int, val attachment: InputAttachment)

fun tagRefs(attachments: List<InputAttachment>): List<TagRef>
fun resolveTagRefs(prompt: String, attachments: List<InputAttachment>): String
fun danglingTagRefs(prompt: String, attachments: List<InputAttachment>): List<String>
```

`resolveTagRefs` заменяет `@метка` на `изображение N (имя_файла)`, где N — позиция файла в списке
вложений, считая с единицы. Эта нумерация обязана совпадать с той, что уходит в `describeAttachments`
— иначе ссылка врёт.

**Метка ≠ тег.** Тег вводится свободно и может состоять из нескольких слов («мокрый асфальт»), а
ссылка в тексте должна иметь границу, иначе `@мокрый асфальт` не отличить от `@мокрый` плюс слово.
Поэтому метка — это тег, у которого пробелы заменены на `_`, а парсер читает токен как
`@` + буквы/цифры/`_`/`-`. Метка показывается в автодополнении, тег — в карточке файла.

**`PromptDiff.kt`**

```kotlin
/** Диапазоны в new, которых не было в old. Словесный LCS: посимвольный даёт нечитаемую кашу. */
fun diffSpans(old: String, new: String): List<IntRange>
```

### `:core-genai` — правки

- `describeAttachments` перенумеровывается: «Изображения по порядку: 1 — trassa_fog_11.jpg, фон
  (ночь, туман); 2 — plash_back_02.png, персонаж (спина, плащ).» Порядок — тот же, в котором картинки
  уходят в `image_url`-части.
- В провайдере перед отправкой промпт проходит `resolveTagRefs`, затем `describeAttachments`.
- `GenaiCatalogSnapshot` получает `textModels: List<TextModelEntry>`.
- `GenaiModelCatalog` получает поле `textModels` (сид из `models.json`).
- `GenaiCatalogService` собирает живые текстовые модели попутно с остальными.

Отдельный тип, а не `GenaiModelEntry`: у той обязательное поле `modality` и хвост из `voices`
и `video`, которым у текстовой модели нет смысла.

```kotlin
@Serializable
data class TextModelEntry(val id: String, val priority: Int = Int.MAX_VALUE, val label: String = "") {
  val displayName: String get() = label.ifBlank { humanModelName(id) }
}
```

### `:app-desktop`

**Промпт-поле переезжает на `TextFieldValue`.** Сейчас это `String`; и подчёркивание, и
автодополнение требуют знать позицию курсора и выделение. Это фундамент под обе фичи, делается один
раз до них.

**`PromptField`** — новый композабл: текстовое поле + `VisualTransformation`, красящая два набора
диапазонов:
- изменённые нейросетью — подчёркивание;
- висячие `@теги` — цвет ошибки.

`OffsetMapping.Identity`: трансформация не меняет длину текста, только оформление.

**`RefinePromptDialog` / `RefinePromptPanel`.** Диалог и его тело разведены — ровно как
`ModelPickerDialog` / `ModelPickerPanel`, чтобы тело попадало в offscreen-снимок (`Dialog` на
десктопе — отдельное окно и в сцену главного экрана не попадает).

Содержимое панели: ряд пресетов, поле своей команды, снизу переключатель модели, кнопки
«Отмена» / «Доработать». Пока идёт запрос — прогресс, кнопки заблокированы. Ошибка показывается
внутри панели, форма при этом не меняется.

**`ModelPickerList` обобщается.** Сейчас принимает `List<GenaiModelEntry>`; чтобы показывать и
текстовые модели, вводится маленький `ModelChoice(id, displayName, vendor)`, в который отображаются
оба типа записей. Один список на оба случая вместо копии.

**`TagAutocomplete`** — попап под полем промпта. Появляется, когда каретка стоит внутри токена,
начинающегося с `@`. Список фильтруется по набранному, каждая строка — миниатюра, метка, имя файла и
роль. Выбор заменяет токен на `@метку`.

**`GenerateScreen`** держит состояние отката:

```kotlin
var promptBeforeRefine by remember { mutableStateOf<String?>(null) }
var refinedSpans by remember { mutableStateOf<List<IntRange>>(emptyList()) }
```

Кнопка «Вернуть оригинал» видна, пока `promptBeforeRefine != null`. Ручная правка текста сбрасывает
`refinedSpans` (смещения устаревают), но `promptBeforeRefine` остаётся — откат должен пережить
опечатку.

## Поток данных

**Доработка:** кнопка → диалог → `PromptRefiner.refine(prompt, instruction, model)` → `Ok` →
`promptBeforeRefine = prompt`; `prompt = result`; `refinedSpans = diffSpans(before, result)`; диалог
закрывается. `Failed` → диалог остаётся, показывает причину.

**Отправка:** `prompt` → `resolveTagRefs` → `describeAttachments` → `chat/completions`.
В историю кладётся ИСХОДНЫЙ промпт с `@тегами`: она должна показывать, что ты писал.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет ключа | Кнопка доработки выключена, та же подпись, что у запуска |
| Сеть/HTTP упали | Причина внутри диалога, промпт не тронут |
| Модель вернула не текст | `Failed` с явным текстом, а не пустое поле |
| `@тег` без файла | Подсветка цветом ошибки, запуск заблокирован |
| Два файла с одним тегом | Различимые метки: `туман`, `туман-2`; в попапе видно миниатюру и имя файла |

## Порядок работ

1. **Фундамент:** промпт-поле на `TextFieldValue` + `PromptField` с трансформацией. Без него ни одна
   из фич не ложится.
2. **Теги:** чистые функции, `describeAttachments`, подсветка висячих, автодополнение. Дешевле и без
   сети.
3. **Доработка:** `PromptRefiner`, текстовые модели в каталоге, диалог, дифф и откат.

Каждый шаг заканчивается прогоном `:core-genai:test` и `:app-desktop:shots`, `traxer check` перед
коммитом, трейлер `Trace: desktop-genai-client-4c63b6`.

## Осознанно не делаем

- Доработку выделенного куска — переписывается весь промпт целиком.
- Пользовательский файл пресетов доработки.
- `GenerationModality.TEXT` и проведение доработки через очередь заданий.
- Историю доработок: откат ровно на один шаг, к тексту до последнего вызова.
