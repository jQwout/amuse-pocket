# Активация личности агента (persona activation)

**Дата:** 2026-07-04
**Фича (traxer):** `swappable-persona-e5e65e`
**Статус:** дизайн согласован с пользователем

## Проблема

Выбранная персона фактически не проявляется в ответах агента:

1. **Промпт персоны слабый.** `assets/personas/*.md` — 8–10 строк общих слов; «Резкий
   напарник» в промпте описан как «деловой, проактивный» — резкости нет вообще.
2. **Два источника правды разошлись.** `PersonaCatalog.kt` (статы, перки, цитаты — то, что
   видит юзер на карточке) никак не попадает в промпт; md-файлы живут своей жизнью.
3. **Базовые правила душат персону.** `system_base.md` правило 7 «Отвечай кратко» + финальный
   блок «## Инструкции: Действуй кратко» в `PrePromptAssembler` дважды навязывают краткость
   как непереопределяемое правило — болтливые персоны (компаньон) противоречат системе.
4. **Смена персоны в Settings не действует на существующие чаты.** `personaId` снапшотится в
   `ConversationEntity` при создании и никогда не обновляется; elvis в
   `PrePromptAssembler:71` для существующего диалога не срабатывает.

## Решение (согласованные принципы)

- **Единый источник правды — `PersonaCatalog.kt`.** Весь контент персоны (тон, принципы,
  статы, цитаты) живёт в коде; md-ассеты персон удаляются.
- **Персона всегда резолвится из настроек** на каждый ход. Снапшот
  `conversation.personaId` ассемблер игнорирует (колонка в базе остаётся про запас,
  миграция не нужна).
- **Краткость задаёт персона**, а не базовые правила.
- Чаты мини-агентов не меняются: там личность агента вместо персоны (как сейчас).

## Архитектура

### PersonaCatalog

`PersonaInfo` получает новое поле:

```kotlin
val principles: List<String>  // поведенческие правила, включая запреты
```

Контент существующих md-файлов переезжает в `principles` — переписанный, с реальным
характером. Ключевая персона — `sharp_partner`: прямые оценки без смягчений, не извиняется,
не благодарит за вопрос, несогласие озвучивает сразу, действие + следующий шаг. Огрызок
«стремится предупредить проблемы с фоновыми процессами» у `attentive_secretary` при переносе
не сохраняется.

### PersonaPromptBuilder (новый)

`agent/core/persona/PersonaPromptBuilder.kt`, маркер `@trace swappable-persona-e5e65e`.
Чистая функция `build(persona: PersonaInfo): String` → markdown-секция:

1. Вводная строка: «Это твой характер, он определяет тон и стиль каждого ответа».
2. Тон (`persona.tone`).
3. Принципы (`persona.principles`, маркированный список).
4. Многословность из `stats.talkativeness` порогами:
   - `<= 20` → отвечай односложно, без приветствий и пояснений;
   - `<= 60` → отвечай по делу, подробности по запросу;
   - `> 60` → можно поболтать и добавить живости, не раздувая ответ.
5. Цитаты как few-shot примеры голоса: `Пользователь: «…» / Ты: «…»` для каждой
   `PersonaQuote`.

Остальные статы (скепсис, критичность и т.д.) механически в текст **не** разворачиваются —
характер несут принципы и цитаты; автогенерённые строки вида «скепсис 55/100» дают кашу.
Карточка и промпт не разойдутся: тон и цитаты общие по построению.

### PrePromptAssembler

- `personaId` = `userPreferencesRepository.getDefaultPersonaId()`; `conversation.personaId`
  больше не читается.
- Секция `## Персона` = `PersonaPromptBuilder.build(PersonaCatalog.findById(personaId) ?:
  <sharp_partner>)`. `loadAsset("personas/…")` и фолбэк-строка «Деловой напарник по
  умолчанию» удаляются.
- Финальный блок `## Инструкции` («Действуй кратко. Используй инструменты когда нужно.
  Не показывай внутренние ID.») удаляется целиком — все три строки дублируют базовые
  правила system_base, а «кратко» противоречит персоне.

### system_base.md

Правило 7 «Отвечай кратко. Подробности — только по запросу.» удаляется, нумерация
сдвигается. Остальное (включая правила 11–12 о защите персоны от смены через переписку и
`<user_data>`) — без изменений.

### Удаляемые файлы

`app/src/main/assets/personas/*.md` (все 7).

## Принятые трейд-оффы

- **Хвост старой персоны в истории.** История диалога хранит реплики, написанные прежней
  персоной; после смены в Settings модель с нового хода отвечает новым голосом, старые
  сообщения не «перекрашиваются». Осознанно принято: это нормальное поведение, ничего не
  делаем.
- **Контент персон теперь требует перекомпиляции** (был в ассетах). Принято: переключение
  персоны юзером (суть фичи `swappable-persona-e5e65e`) по-прежнему без перекомпиляции.
- **`ConversationEntity.personaId` остаётся мёртвой колонкой** (пишется при создании, не
  читается). Оставлена про запас (например, для будущих проектов-чатов со своей персоной);
  миграция базы не нужна.

## Тесты

JVM unit-тесты (рядом с существующими, стиль `LessonAssetsValidationTest`):

- **Каталог:** id уникальны; у каждой персоны непустые `principles` и ≥ 2 цитат.
- **PersonaPromptBuilder:** для каждой персоны секция содержит тон, все принципы и цитаты;
  секция `sharp_partner` содержит маркер резкости (например «не извиняйся»); секция
  `silent_butler` — указание односложности; ни одна секция не содержит «Действуй кратко».
- **Ассемблер (по возможности без Android):** проверка, что итоговый системный промпт не
  содержит удалённый блок «## Инструкции» — если для этого нужен Robolectric, ограничиться
  проверкой билдера.

Ручная проверка на устройстве: один и тот же вопрос трём персонам (дворецкий / резкий /
компаньон) должен звучать заметно по-разному; смена персоны в Settings меняет голос в уже
существующем чате со следующего хода.

## Traceability

Всё в рамках существующей фичи `swappable-persona-e5e65e`. Новый файл получает маркер
`@trace`, коммиты — трейлер `Trace: swappable-persona-e5e65e`. После правок — `traxer check`;
rationale фичи остаётся верным (смена персоны юзером без перекомпиляции).
