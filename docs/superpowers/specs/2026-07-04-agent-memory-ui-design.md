# Спека: экран «Память агента» (memory inspector UI)

Дата: 2026-07-04
Статус: дизайн согласован (вариант A — один экран с вкладками)

## Зачем

Доверие и приватность: пользователь должен видеть, что агент про него назапоминал
(факты, профиль, эпизоды действий), и уметь заставить агента «забыть» любую запись.
Это MVP-пункт №4 из ревью архитектуры памяти (2026-07-04).

## Охват

Показываем три слоя памяти:

- **Профиль** — факты `category=profile` (пишутся онбордингом через `saveUserProfile`).
- **Факты** — все остальные факты key/value (`preference`, `general`, состояние мини-агентов по префиксам).
- **Эпизоды** — записи `tool_call` из `EpisodeEntity` (авто-запись в ReactLoopRunner).

Действия: **удаление** — поштучно и «очистить вкладку» с подтверждением.
Редактирование, поиск, экспорт, provenance — сознательно за скобками (v2).

## Навигация и вход

- Новый route `agent_memory` в NavHost (`MainActivity.kt`).
- Точка входа одна: пункт «Память агента» в `SettingsScreen` (строка-ряд в стиле
  IntegrationRow: иконка в круге 44dp + заголовок + подпись
  «Что агент запомнил: профиль, факты, эпизоды»).

## Экран

`AgentMemoryScreen` (`app/src/main/java/com/example/ui/memory/AgentMemoryScreen.kt`):

- Каркас — `AcademyCollapsingScaffold`, заголовок «Память агента».
- Под тулбаром `TabRow`: **Профиль · Факты · Эпизоды**.
- В actions тулбара — overflow-меню с пунктом «Очистить вкладку»
  (AlertDialog-подтверждение; удаляет записи только активной вкладки).
- Пустая вкладка → empty state «Агент пока ничего не запомнил».

### Вкладка «Профиль»

- Источник: `FactDao` факты `category=profile`.
- Карточка профиля: известные ключи маппятся на человеческие подписи
  (`user.name` → «Имя», `user.preferred_address` → «Обращение», `user.age` → «Возраст»,
  `user.gender` → «Пол», `user.religion` → «Религия», `user.extra_info` → «О себе»);
  неизвестные ключи показываем как есть.
- У каждой строки — корзина: удаляет один факт профиля.

### Вкладка «Факты»

- Источник: все факты кроме `category=profile`.
- Группировка секциями (чистая функция во ViewModel):
  1. Сначала по мини-агентам: факт, чей `key` начинается с одного из
     `stateKeyPrefixes` агента из ростера (например `lang:`, `grammar:`,
     `goal:languages` → секция «Репетитор», иконка агента).
     Префикс имеет приоритет над категорией.
  2. Остальные по категории: «Предпочтения» (`preference`), «Общее» (`general`).
- Пустые секции не показываются.
- Строка факта: `key` мелко вторичным цветом, `value` основным текстом,
  дата `updatedAt`, корзина с удалением.

### Вкладка «Эпизоды»

- Источник: `EpisodeDao`, последние ~200 записей.
- Строка: тип эпизода (имя тула), относительное время («2 ч назад»),
  свёрнутые `payload`/`outcome`; тап разворачивает (моноширинный текст,
  обрезка длинных значений).
- Удаление поштучно + «Очистить вкладку» из меню.

## Данные и реактивность

- Новый `AgentMemoryViewModel` — DI по существующему паттерну
  (`@Inject` + `@ContributesIntoMap(AppScope::class)` + `@ViewModelKey`).
- Зависимости: `MemoryRepository` + ростер мини-агентов (для маппинга префикс → имя/иконка агента).
- В DAO добавить observe-методы, чтобы UI обновлялся реактивно (после удаления
  и пока агент пишет память в фоне):
  - `FactDao.observeAll(): Flow<List<FactEntity>>`
  - `EpisodeDao.observeRecent(limit): Flow<List<EpisodeEntity>>`
  - недостающие `deleteById` / `deleteAll`-варианты для фактов и эпизодов
    (сквозь `MemoryRepository`).

## Traceability

Новая фича → новый traxer id (рабочее имя `memory-inspector-ui`):

- запись в `traceability.yaml`: title «UI-инспектор памяти агента», rationale —
  «доверие и приватность: юзер видит и может стереть, что запомнил агент»;
- маркеры `@trace` в `AgentMemoryScreen` и `AgentMemoryViewModel`;
- трейлер `Trace: <id>` в коммитах фичи.

## Тесты

- Юнит-тест группировки фактов: префикс мини-агента имеет приоритет над категорией;
  `preference`/`general` раскладываются по своим секциям; пустые секции отсутствуют.
- Остальное — ручная проверка на устройстве (вкладки, удаление, очистка, empty state).

## Вне охвата (v2+)

Редактирование значений фактов, поиск по памяти, provenance (источник факта),
экспорт/бэкап, ссылка на граф памяти с этого экрана, summary диалогов.
