# codebase-memory-mcp — план подключения

Статус: **запланировано, не начато.** Делать **после сдачи** (M4, 4 ноября 21:00 ET).
Источник: <https://github.com/DeusData/codebase-memory-mcp>, лицензия MIT.

## Что это

Локальный MCP-сервер, который строит графовую память репозитория: символы, вызовы, импорты,
связи кода с документацией и инфраструктурой. Нативный бэкенд на C, грамматики tree-sitter вшиты
в бинарь, база — SQLite в `~/.cache/codebase-memory-mcp/`. Наружу — 17 MCP-тулов
(`index_repository`, `search_graph`, `search_code`, `trace_path`, `get_architecture`,
`detect_changes`, `check_index_coverage` и прочие), каждый работает и как разовая CLI-команда.
Телеметрии нет. Kotlin — в верхнем тире поддержки (Hybrid LSP: импорты, extension-функции,
companion, scope-функции, data-классы).

## Зачем нам

В проекте 487 файлов `.kt` и ~86 тысяч строк. Субагенты оркестратора (`implementer`, `verifier`)
каждый раз ищут одно и то же заново через grep/glob и читают файлы целиком — на это уходят и токены,
и шаги. Граф отвечает на структурные вопросы прямо: кто зовёт эту функцию, что затронет правка,
какие тесты относятся к этому коду.

С traxer не конкурирует и не пересекается: `traceability.yaml` хранит **почему** фича существует
(rationale, решение владельца), граф — **где код и что с чем связано**. ADR-тулы сервера нам не нужны,
реестр «почему» у нас уже есть — не дублировать.

## Почему не сейчас

1. Установщик настраивает до 45 клиентских поверхностей и умеет писать инструкции, скиллы, профили
   агентов и хуки — то есть лезет в `.claude/` и в `CLAUDE.md`. Сейчас `.claude/` — рабочий инструмент
   оркестратора в окне хакатона; ломать его нечем оправдать.
2. Выигрыш инструмента — в токенах на будущих задачах. До 4 ноября задачи уже расписаны по вехам
   (`orchestrator/ROADMAP.md`), и ни одна из них этим не ускорится.

## Порядок работ

0. **Ветка `chore/codebase-memory-mcp`.** Ничего прямо в `mvp`: установщик правит файлы репозитория,
   и его diff надо читать построчно.
1. **Установка.** На Windows — `install.ps1`. Сначала посмотреть его ключи: нужна установка **только**
   для этого проекта и Claude Code, а не раскатка по всем клиентам на машине. Сразу после —
   `git status` и `git diff`: что он тронул в репо. Бинарь сам не обновляется, обновление — повторный
   прогон скрипта.
2. **Первая индексация.** `index_repository`, затем `index_status`. Замерить время и размер базы
   на 86 тысячах строк — это и будет ответ, годится ли инструмент вообще.
3. **Проверить, что индексатор уважает `.gitignore`.** Критично: в дереве лежат `build/`, `.gradle/`
   и `.claude/worktrees/` — вложенные копии всего репозитория. Если он их проиндексирует, граф
   раздуется и выдаст дубли классов (ровно та грабля, на которой уже спотыкалась индексация
   Android Studio). Если не уважает — ограничить корень или список исключений до запуска.
4. **Артефакт графа `.codebase-memory/graph.db.zst` — не коммитить.** Репозиторий станет публичным,
   `.git` уже 149 МБ, и в `CLAUDE.md` уже записано правило: мегабайты бинарей в историю не идут
   (поэтому и `orchestrator/evidence/` вне git). Добавить `.codebase-memory/` в `.gitignore`.
   Захочется делиться базой — релизный артефакт, не история.
5. **Настройки.** `config set watcher_enabled false` (или `auto_watch false`): ещё один файл-вотчер
   по всему дереву рядом с Gradle и Android Studio на Windows — лишний источник тормозов.
   Индексировать по требованию, перед задачей. `auto_index` включать только если шаг 2 показал,
   что индексация быстрая.
6. **`.mcp.json` в корне** (сейчас его нет вообще) — проектный конфиг, чтобы сервер видели все агенты
   репозитория. Проверить, что внутри нет абсолютных путей и ничего машинно-зависимого: файл станет
   публичным.
7. **Разрешения.** В `.claude/settings.json` в `allow` добавить `mcp__codebase-memory*`, иначе каждый
   вызов — промпт владельцу.
8. **Научить субагентов им пользоваться.** По строчке в `.claude/agents/implementer.md` и
   `verifier.md`: сначала спроси граф, потом читай файлы. Без этого инструмент будет стоять
   установленным и неиспользуемым — это главная причина, по которой такие штуки не приживаются.
9. **Померить пользу.** Взять одну реальную задачу из роадмапа, сделать её с графом, сравнить число
   шагов с тем, как обычно. Выигрыша нет — снять и не тащить публичный репозиторий лишней зависимостью.

## Что решает владелец

- Ставить ли сервер глобально на машину или только для этого проекта.
- Коммитить ли `.mcp.json` в публичный репозиторий (будет видно, какими инструментами собрано).
- Нужен ли CBM Lens — браузерный UI с 3D-графом. Это бета, а встроенный чат тянет ~567 МБ весов
  модели и требует WebGPU. Для нашей задачи не нужен; ставить только из любопытства.

## Риски

| Риск | Что с ним делать |
|---|---|
| Установщик правит `CLAUDE.md` и `.claude/` | Только на ветке, diff читать построчно, лишнее откатывать |
| Windows Defender помечает релизные бинари (известный ложняк, описан в README) | Ожидать на первом шаге; это будет первый затык на машине владельца |
| Индексация вложенных `.claude/worktrees/` | Шаг 3 — до первой индексации, не после |
| Графовый артефакт в истории публичного репо | Шаг 4: `.gitignore`, не коммит |
| Ещё один фоновый демон на Windows | Шаг 5: вотчер выключить, индексировать по требованию |

## Чего инструмент не умеет

Статические пути вызовов — это возможные связи, а не то, что происходит в рантайме. Умный подбор
тестов в CI — экспериментальный и пока только для C/C++. Про Android и Gradle в README нет ничего:
граф будет про Kotlin-код, а не про конфигурацию сборки.
