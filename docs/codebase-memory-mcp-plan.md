# codebase-memory-mcp

Статус: **подключено 30 октября 2026** по просьбе владельца. План предполагал «после сдачи»;
владелец решил иначе. Источник: <https://github.com/DeusData/codebase-memory-mcp>, MIT, версия 0.12.1.

Локальный MCP-сервер с графовой памятью репозитория: символы, вызовы, импорты, связи кода с
документацией. Отвечает на структурные вопросы — кто зовёт функцию, что затронет правка, какие модули
есть — вместо того чтобы читать файлы подряд. Kotlin у него в верхнем тире поддержки.

## Что стоит и где

- Бинарь `codebase-memory-mcp.exe` 0.12.1 — `%LOCALAPPDATA%\Programs\codebase-memory-mcp`,
  установщик дописал этот путь в PATH пользователя.
- Поставлен с `--skip-config`: ни одна из 45 клиентских поверхностей не настраивалась.
  `~/.claude.json`, `~/.claude/settings.json`, `~/.claude/skills` и `~/.claude/agents` не тронуты —
  проверено после установки. Никаких глобальных хуков на Grep/Glob/Bash, которые он ставит по умолчанию.
- Сервер объявлен только для этого репозитория — [`.mcp.json`](../.mcp.json).
- Кеш, база графа и логи — `~/.cache/codebase-memory-mcp/`.
- Обновление: повторный прогон `install.ps1`, он лежит рядом с бинарём. Сам себя не обновляет.

## Как настроено и почему

| Что | Значение | Почему |
|---|---|---|
| `CBM_WORKERS` | `1` (в `.mcp.json`) | Иначе индексация падает, см. ниже. **Обязательно.** |
| `watcher_enabled` | `false` | Ещё один файл-вотчер по всему дереву рядом с Gradle и Android Studio на Windows — лишний источник тормозов |
| `auto_watch` | `false` | То же: никаких регистраций наблюдения при старте сессии |
| `auto_index` | `false` (по умолчанию) | Индексируем руками, когда это нужно |
| `ui_enabled` | `false` | Пришёл включённым (`true`), хотя документация обещает `false`. Это локальный веб-UI CBM Lens на порту 9749; он нам не нужен, и слушающий порт на машине — без надобности |
| `.cbmignore` | [файл](../.cbmignore) | Вложенные воркtree и сборка |
| `.codebase-memory/` | в `.gitignore` | Графовый артефакт — мегабайты бинаря, а репозиторий публичный. Запись выключена по умолчанию (`persistence: false`), файл игнорируется на случай, если кто-то её включит |

## Windows: параллельный экстрактор падает

Прогон по умолчанию не доходит до конца. Воркер падает с `-1073741819` (access violation),
перезапускается и падает снова — **каждый раз на другом файле** (160, 192, 240, 300, 373 из 661), то
есть дело не в конкретном файле, а в самом параллельном экстракторе. 137 секунд и пустой результат.

С `CBM_WORKERS=1` — 19,8 секунды и целый граф. Однопоточно не только надёжнее, но и **в семь раз
быстрее**, так что терять на этом нечего.

Это известная открытая бага: `docs/WINDOWS_TROUBLESHOOTING.md` в их репозитории, тикеты #1130, #1132,
#1145. Поэтому `CBM_WORKERS=1` стоит в `.mcp.json` и нужен каждому ручному вызову.

## Переиндексация

Вотчер выключен, автоиндекс выключен — граф стареет сам. Пересобрать (PowerShell):

```powershell
$env:CBM_WORKERS = "1"; codebase-memory-mcp cli --progress index_repository --repo-path <абсолютный путь к репозиторию>
```

Полезное рядом: `codebase-memory-mcp cli detect_changes --project <имя>` — что разошлось с индексом;
`codebase-memory-mcp cli list_projects --format json` — имя проекта для остальных команд.
Имя этого репозитория в графе — `C-Users-jqwou-StudioProjects-ai-open-pocket-2`.

## Первый индекс, 30 октября

9716 узлов, 52299 связей, 19,8 секунды. Исключено: `.claude` (а с ним и `.claude/worktrees`), `.git`,
`.gradle`, `.idea`, `.kotlin` и 96 файлов по `.gitignore` и по суффиксам. Дубля классов из вложенных
чекаутов нет. Частично разобраны два файла: `LessonAssetsValidationTest.kt:243` и `gradlew:180` —
на структуру графа это не влияет.

Проверено запросами: `search_graph` находит `ReactLoopRunner` (класс, строки 75–609, 15 входящих
связей); `trace_path` по `riskFor` честно отвечает «неоднозначно, 10 совпадений» и даёт
квалифицированные имена.

## Кто этим пользуется

Правило «сначала спроси граф, потом читай файлы» прописано агентам
[`implementer`](../.claude/agents/implementer.md) и [`verifier`](../.claude/agents/verifier.md).
У проверяющего своя задача: `trace_path` по изменённым функциям показывает, кто их ещё зовёт — частая
причина FAIL в том, что поправлено одно место из трёх.

Разрешение `mcp__codebase-memory-mcp` добавлено в `.claude/settings.json`, иначе каждый вызов
спрашивал бы подтверждения.

## Чего не сделано

- **Польза не измерена.** Шаг 9 исходного плана: взять реальную задачу, сделать её с графом и сравнить
  число шагов с обычным. Без этого «экономит токены» — обещание из их README, а не наш факт.
- **`CLAUDE.md` не тронут.** Правило о графе знают только два агента оркестратора; основная сессия
  видит инструменты, но не инструкцию предпочитать их Grep.
- **CBM Lens не ставили** — браузерный UI с 3D-графом, бета, чат тянет ~567 МБ весов.
- **ADR не ведём.** Сервер предлагает `manage_adr`; реестр «почему» у нас уже есть — это
  `traceability.yaml` с rationale. Не дублировать.
