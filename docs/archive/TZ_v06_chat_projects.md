# ТЗ v0.6: Чат-проекты (Архетип 3) — языковой тренер и аи-тренер

> **Версия:** 0.6 · **Дата:** 2026-06-15 · **Статус:** черновик на подумать (не согласовано)
> Дополняет [TZ_v05_widgets_apps.md](TZ_v05_widgets_apps.md). Там — Архетип 1 (апы-композиции). Здесь — **Архетип 3** из §12 v0.5: scoped разговор + план + память.

---

## 1. TL;DR

**Чат-проект** = выделенный разговор под одну цель, посеянный спец-инструкциями (персоной проекта) и подкреплённый **персистентным планом и памятью**, scoped к проекту. Аналог *Project* в Claude. Это **не карточки** — это режим чата.

Первая реализация — **языковой тренер** (EN/DE): просто говорить с пользователем на языке, мягко исправлять, помнить уровень/план/ошибки. Та же машинерия даёт **аи-тренера**.

Ключевое: механизм уже есть в зачатке — **уроки роадмапа** (чат + впрыснутый сценарий через `PrePromptAssembler`). Обобщаем «фиксированный линейный урок» → «открытый stateful-проект».

| Решение | Почему |
|---|---|
| Проект = `Conversation` + project-definition + scoped memory namespace | переиспользуем существующее, минимум нового кода |
| Определения проектов — предзаполненные (`assets/projects/*.md`), как персоны | авторишь руками; LLM не создаёт проекты в v1 |
| План/прогресс — в `MemoryRepository` под неймспейсом проекта | факты/эпизоды уже есть, новый стор не нужен |
| Не карточки | это разговор; виджеты опциональны (`choice`/`lesson_complete` для упражнений) |

---

## 2. Чем отличается от уроков роадмапа

| | Урок (сейчас) | Чат-проект (новое) |
|---|---|---|
| Длина | конечный, скриптованный | открытый, длящийся |
| Состояние | прогресс = пройден/нет | эволюционирующий план + накопительная память |
| Контент | фикс. сценарий `prompts/roadmap/lX.md` | инструкции проекта + динамический план из памяти |
| Память | почти нет | центральная (уровень, ошибки, словарь, цели) |

Урок — частный случай чат-проекта. Машинерия запуска (`RoadmapViewModel.openLesson` → tutorial-conversation → инжект через `PrePromptAssembler`) обобщается.

---

## 3. Архитектура

```
Вход «Проекты» (как RoadmapScreen) → список предзаполненных проектов
  ↓ tap: openProject(projectId)
ConversationRepository.createConversation(title, personaId = project.persona, kind = PROJECT)  [reuse]
  ↓
PrePromptAssembler собирает системный промпт:
  system_base.md
  + project-instructions  (assets/projects/<id>.md)
  + scoped memory         (план, уровень, недавние ошибки/слова — факты/эпизоды по namespace)
  + windowed history      (как сейчас)
  ↓
обычный ReAct-цикл (AgentLoopOrchestrator, без изменений)
  ↓
агент по ходу диалога пишет прогресс через memory-тулы под namespace проекта
```

Новое: формат project-definition, memory-namespace, ветка в `PrePromptAssembler` на инжект проектного контекста, признак проекта у `Conversation`, экран-вход «Проекты». Всё остальное — существующее.

---

## 4. Формат определения проекта (предзаполненный)

`app/src/main/assets/projects/<id>.md` — как персона, но с проектной семантикой:

```yaml
---
id: lang_tutor_en
title: "Английский — разговор"
persona: friendly_companion        # базовая персона, поверх которой инструкции
memory_namespace: "lang.en"        # префикс ключей памяти проекта
entry_message: "Hi! Let's chat in English. Tell me about your day."
---
# Инструкции проекта
- Веди диалог на английском, адаптируй сложность под уровень из памяти.
- Мягко исправляй: покажи ошибку и правильный вариант, не ломая поток.
- Веди план: уровень, темы, повторяющиеся ошибки, новые слова.
- Заканчивай сессию мини-итогом + одним маленьким заданием.
```

Проекты пишутся **руками**. LLM их не генерирует (v1).

---

## 5. Память проекта (namespace)

- **Факты** (`proj.<ns>.*`) — устойчивое: `lang.en.level=B1`, `lang.en.goal=...`, `lang.en.plan=...`
- **Эпизоды** — лог сессий, ошибки, новые слова (`type=lang_session`, payload scoped к проекту)
- `PrePromptAssembler` подтягивает top-N по namespace проекта в системный промпт **каждый ход**
- Агент обновляет через существующие `remember_fact` / `recall_episodes` — с явным namespace-параметром **или** соглашением по префиксу ключей (см. §13)

---

## 6. Жизненный цикл

- **Первый вход:** опц. placement — короткий диалог или `choice`-квиз на уровень → пишет `level`
- **Каждая сессия:** `PrePromptAssembler` инжектит план + уровень + последние ошибки → разговор → агент дописывает прогресс
- **Возврат:** продолжение с учётом памяти — агент «помнит», где остановились
- **Виджеты:** опционально `choice` (быстрые упражнения), `lesson_complete` (конец сессии)

---

## 7. Языковой тренер (первый инстанс)

- **Языки v1:** EN, DE. В онбординге уже есть LANGUAGE-степ (RU active, EN/DE locked) — здесь они оживают как проекты.
- **Поведение:** говорит на целевом языке, адаптация под уровень, мягкая коррекция (ошибка + правильно), в конце — резюме + задание.
- **Память:** `level`, план/темы, recurring mistakes, vocab.
- Голос (STT/TTS) — **вне скоупа** (v1.1), пока только текст.

---

## 8. АИ-тренер (второй инстанс, тот же механизм)

- **Инструкции:** цели пользователя, ведёт todo + заметки проекта, периодические чек-ины.
- **Память:** цели, активные задачи, прогресс.
- Может звать `schedule_task` для чек-инов и использовать **апы-композиции** (`todo`/`notes` из Архетипа 1) внутри проекта — точка стыковки двух архетипов.

---

## 9. Что переиспользуем / новое

| reuse | `Conversation`, `ConversationRepository`, personas, `MemoryRepository` (facts/episodes), `PrePromptAssembler`, паттерн запуска `RoadmapViewModel.openLesson`, ReAct-цикл |
|---|---|

---

## 10. Безопасность / границы

- Проекты предзаполнены (assets); LLM не создаёт новые проекты в v1.
- Память scoped по namespace — проект не лезет в чужой контекст.
- Нет нового хранилища и нет сети сверх LLM.
- Голос/мультимодальность — вне скоупа.

---

## 11. Стейджи

### Stage A — Каркас проекта · ~1 день
Признак проекта у `Conversation` (`kind`/`projectId`), формат `assets/projects/`, один проект `lang_tutor_en`, запуск из «Проектов» (или временно из роадмапа).
**Done when:** тап → открывается проектный чат с entry_message и проектной персоной.

### Stage B — Инжект контекста + память · ~1–1.5 дня
`PrePromptAssembler`: подмешивает project-instructions + scoped memory; агент читает/пишет namespace.
**Done when:** агент использует план/уровень из памяти и дописывает прогресс по ходу.

### Stage C — Уровень + персистентность · ~1 день
Placement (уровень), сессионный итог, продолжение между запусками.
**Done when:** закрыл/открыл → агент помнит уровень и где остановились.

### Stage D — Обобщение · ~1 день
Второй язык (DE) + аи-тренер как второй проект — проверка, что машинерия общая.
**Done when:** два разных проекта работают на одном механизме без спец-кода.

### Stage E — Полировка · ~0.5 дня
Пустая память, длинная история (саммаризация уже есть), edge cases.

**Итого ~4.5–5 дней.**

---

## 12. Что осознанно НЕ делаем (v1)

- Пользовательские проекты «с нуля» (юзер/LLM создаёт проект) — v1.1.
- Голос (STT/TTS) — v1.1.
- Связь проектов между собой, шаринг.
- Свой стор сверх памяти (facts/episodes).

## 13. Открытые вопросы

1. Вход: отдельный таб «Проекты», секция в роадмапе или в списке чатов?
2. Namespace в памяти: явный параметр в memory-тулах или соглашение по префиксу ключей?
3. `Conversation`: новый `kind` (lesson/project/chat) или переиспользовать `isTutorial` + `projectId`?
4. Placement уровня: `choice`-квиз или свободный диалог?
5. Языки: только EN/DE в v1 или сразу заложить расширяемость в коде?
