# Обновляемые driven-UI карточки (card_id + upsert) — дизайн-идея

Статус: **идея, не реализовано** (записано 2026-07-03 по итогам ресёрча генеративного UI).

## Суть

Сейчас карточка «замораживается» в момент хода: `render_card` → JSON → `addMessage(cardSpec)`,
и дальше она статична. В веб-чатах (Vercel AI SDK `streamUI`, виджеты ChatGPT) карточки
обновляются in-place: у карточки есть стабильный id, состояние живёт в реактивном сторе,
UI подписан на стор.

У нас реактивный стор уже есть — Room: лента идёт через `observeMessages` Flow, а парсинг
в `ChatScreen.kt` (~1035) завязан на `remember(message.cardSpec)`. Значит, **если строку
`cardSpec` в БД обновить — карточка перепарсится и перерисуется сама**, рендер-слой
(`DrivenUiEngine`) не трогается вообще.

## Недостающие три части

1. **`card_id` в спеке.** Необязательный параметр в `render_card`
   (`app/src/main/java/com/example/agent/tools/RenderCardTool.kt`), в описании тулзы —
   «передай тот же card_id, чтобы обновить ранее показанную карточку». Спека:
   `{"card_id":"...","template":"...","params":{...}}`. Парсер незнакомое поле игнорирует —
   обратная совместимость бесплатно. Отдельная тулза `update_card` не нужна:
   «тот же card_id = обновление» проще для модели.

2. **Upsert вместо только-вставки.** В `ConversationRepository` — `updateCardSpec(messageId,
   newSpec)` (Room UPDATE; сейчас есть только `addMessage`). В `ChatViewModel` (обработчик
   результатов тулз, ~438–467): есть в диалоге карточка с таким `card_id` → обновляем её
   строку, нет → добавляем сообщение как сейчас. Искать по `card_id` внутри `cardSpec`
   (первая карточка хода прикреплена к текстовому сообщению, а не живёт отдельно).

3. **Живость во время хода.** Карточки сейчас извлекаются только в `AgentEvent.Completed` —
   несколько `render_card` за ход схлопываются в конец. Перенести upsert в обработчик
   `AgentEvent.ToolCompleted` (~426): тулза отработала → карточка сразу в БД → сразу на
   экране; следующий вызов с тем же id мутирует её же. Из `Completed` извлечение убрать,
   чтобы не задвоить.

Бонус: тот же `updateCardSpec` делает персистентным пользовательский интерактив
(чекбоксы `todo_list`, таймер) — сейчас это локальный `remember`, теряется при скролле
(LazyColumn пересоздаёт композабл) и перезапуске. Колбэк карточки пишет изменённые params
обратно в cardSpec + (опционально) шлёт back-channel агенту — стыкуется с дизайном
back-channel v2.

Пример: агент «Бюджет» показал `chart_bar` за неделю → юзер добавил расход → агент вызвал
`render_card` с тем же `card_id` → график обновился на месте, а не вырос вторым ниже.

## Открытые вопросы по UI/UX (почему пока не делаем)

- **Обновление вне вьюпорта.** Юзер проскроллил выше — карточка обновилась незаметно.
  Нужен индикатор «обновлено» / бейдж / автоскролл? В веб-чатах живой виджет обычно
  либо последнее сообщение, либо закреплён отдельно от ленты.
- **Чат — это журнал.** Обновляемая карточка ломает хронологию: прошлое состояние
  исчезает («был график на 3 траты — стал на 5», истории нет). Варианты: пометка
  «обновлено», история версий, или осознанно принять «живой объект в ленте».
- **Конфликт с локальным вводом.** Если юзер заполняет `form`, а агент в этот момент
  обновил cardSpec — `remember(cardSpec)` сбросит ввод. Правило: не апдейтить карточки
  с активным вводом (или мержить state отдельно от layout).
- **Анимация.** Замена cardSpec перерисует карточку резко — нужен animateContentSize /
  crossfade, иначе будет дёргаться.
- **Альтернатива ленте.** Возможно, «живой» карточке место не в чате, а на закреплённой
  панели / экране мини-агента — тогда это сшивается с планом Remote Compose экранов
  (см. ресёрч: чат-карточки остаются на render_card, экраны агентов — кандидат на
  Remote Compose + Ktor).
- **Схема данных.** Для часто обновляемых карточек стоит разделить `params` (layout)
  и `state` (изменяемые значения), чтобы апдейты не переписывали всю спеку.
